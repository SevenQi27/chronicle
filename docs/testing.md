# 测试与验证

## 自动化测试

配置项目 `.env` 中的 Neo4j 连接信息，确认服务可用后运行：

```sh
uv sync --locked
uv run chronicle init
uv run chronicle check
uv run pytest -q
```

数据库测试使用随机 namespace，结束后清理自身数据。MCP 测试会启动独立服务进程，验证协议握手、工具调用和跨会话读取。模型接口测试使用模拟 HTTP 响应。

| 测试文件 | 覆盖范围 |
| --- | --- |
| `test_experiences.py` | 经历、认识、证据、关联、模糊时间和待确认内容 |
| `test_time.py` | 生效边界、迟到信息、纠错、规则期限、计划变化和数据隔离 |
| `test_timeline.py` | 时间推进产生的状态变化 |
| `test_service.py` | 提取调用、关键词与向量检索、时间视角和错误处理 |
| `test_cli.py` | 标准输入、文件输入、退出码和 worker 生命周期 |
| `test_concurrency.py` | 重复提交、版本竞争、提取失败竞争、读取视图和并发检查 |
| `test_retrieval.py` | 索引候选、短名称匹配、原生向量索引和启动行为 |
| `test_neighbor_regressions.py` | 大量旧版本、关联移除、稳定排序、截断标记和历史视角 |
| `test_ingest_context.py` | 关键词落空后的实体及近期来源上下文 |
| `test_mcp.py` | MCP 子进程、通用对象写入、关联查询和客户端配置 |
| `test_ui.py` | 只读图谱、版本与证据关系、分区隔离、截断及本地 HTTP 访问边界 |

## 结构化演示

```sh
uv run chronicle demo
```

演示使用真实 Neo4j、模拟日期和独立临时分区，覆盖经历之间的关联、认识的证据追溯、经历更正后的重新审视，以及旧认知查询。运行结束后清理演示数据。

## Agent 对话验收

连接 MCP 后，在独立测试 namespace 中验证以下行为：

1. 输入包含背景、感受和不确定时间的自然语言经历，检查生成的经历是否保留原意。
2. 开启没有前文的新会话，以不同措辞提问，检查能否找到相关经历及原始来源。
3. 让 Agent 归纳认识，检查是否引用经历，并区分用户明确表达与系统推测。
4. 更正原始经历，检查版本是否保留、相关认识是否需要重新审视。
5. 指定过去的 `known_at`，检查查询和详情读取是否都遵守获知时间边界。
6. 在两个 Agent 中使用相同 namespace，检查跨宿主写入与读取。

自动化测试验证结构和调用行为；上述步骤用于评估宿主模型的提取和回忆质量。协议连接成功与模型对话完成应分别确认。

真实时间检查可使用短期规则或计划：设定明确的截止时间，保持服务运行，在截止前后运行 `chronicle state` 和 `chronicle checks` 查看状态。规则应在到期后失效；缺少完成证据的计划应保持结果待确认。

## CI

GitHub Actions 在独立 Neo4j 服务上执行同一套测试和构建。测试凭据仅用于临时服务；真实模型验收需在具备宿主模型凭据的环境单独进行。
