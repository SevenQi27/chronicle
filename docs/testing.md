# 测试与验证

## 自动化测试

配置项目 `.env` 中的 Neo4j 连接信息，确认服务可用后运行：

```sh
uv sync --locked
uv run chronicle init
uv run chronicle check
uv run pytest -q
```

数据库测试使用随机 namespace，结束后清理自身数据。MCP 测试会启动独立服务进程，验证协议握手、工具调用和跨会话读取。模型接口测试使用模拟 HTTP 响应。

## 查询与生命周期回归（2026-11-13）

`test_lifecycle.py` 使用隔离 Neo4j 分区覆盖：多种查询表达去重、历史与当前命中依据、显式会话/项目/来源筛选及邻居和上下文范围、精确状态冲突保留、旧采集元数据回填、撤回全版本与后续更新、恢复可见性、依赖认识复核、永久遗忘共享来源/关联/依赖闭包、旧预览 token 失效、采集队列正文清理及跨队列重放防护。

备份测试实际导出 JSON 并恢复到另一空分区，比较来源正文、版本详情及时间截止点，核对关系、状态、撤回和遗忘标记、向量索引与已应用来源重试；另外验证校验和损坏、目标 token 不匹配、非空目标及导出覆盖拒绝。CLI 和原生 stdio MCP 测试实际调用新增入口。

```sh
uv run pytest -q tests/test_lifecycle.py tests/test_cli.py tests/test_mcp.py
```

`test_lifecycle_review.py` 另覆盖 UTC / 非 UTC 时间表示在生效整秒、同秒微秒边界的排序和状态，排除已取代及已更正计划，共享来源在实际 ingest 提取上下文中的保留，撤回期间计划/认识的到期检查保持待处理及恢复后单次触发，撤回检查不占 worker 批次，以及关联删除的 Neo4j `EXPLAIN` 使用关系属性索引、不出现全库关系扫描。10 个用例在修复前全部失败，修复后全部通过。

这些验证不等于大型数据库吞吐量、外部副本删除或介质安全擦除保证。

## 存取质量基线（2026-11-12）

本轮直接阅读本地参考仓库，没有引入它们的依赖或运行其服务：

| 参考快照与代码 | 采用的思路 | 本轮没有照搬的做法 |
| --- | --- | --- |
| Graphiti `ebef986`，`graphiti_core/search/search_utils.py:1786` | 按对象聚合多路候选，分别验证排名与返回的数据量 | 未更换现有融合排名；本轮质量用例没有提供改排名的必要证据 |
| claude-mem `5b4a208`，`src/shared/progressive-search.ts:155`、`:252` | 短索引后按需展开，省略内容时明确标记 | 不默认过滤原始 prompt，也不把完整详情改成强制截断或超限拒绝；来源摘要由调用方选择 |
| Mem0 `f1791da`，`mem0/memory/main.py:1009` | 区分重复提交和实际新增，验证持久化结果 | 不按相同文本跨事件丢弃记录；只优化相同来源及提取载荷的成功重放 |

运行方式：

```sh
uv run python scripts/benchmark_memory.py \
  --samples 20 --revisions 128 --output data/benchmarks/current.json
```

数据为合成数据：160 条无关经历、同一经历的 128 个版本、16 条消息逐步形成的采集对话，以及混合检索用的一轮对话。模型和嵌入服务在脚本内明确关闭。每轮创建随机 `benchmark-memory-*` 分区，在 finally 中删除并独立核对清理结果。真实用户数据不参与写入测试。

优化前版本为 `dce7ebf`，通过临时目录加载该提交的源码；优化前后运行同一个脚本和数据集。JSON 内保留了实际加载代码的 SHA-256。计时先预热 2 次，再测 20 次；指标采样另跑一次，不把诊断 JSON 序列化计入耗时。`statements`、`returned_rows`、`decoded_row_json_bytes` 统计 `_run` 读取接口，写事务内部语句不在其中，另以 `write_transactions` 记录。解码 JSON 字节是数据量估计，不是 Bolt 网络传输字节。

原始结果：[memory-before.json](benchmarks/memory-before.json)、[memory-after.json](benchmarks/memory-after.json)。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 当前版本读取，128 个版本：读取返回行数 | 129 | 2 |
| 同一读取：解码行 JSON 字节 | 2,062,618 | 16,137 |
| 同一读取：中位耗时 / P95（ms） | 19.340 / 24.740 | 1.200 / 1.789 |
| 多版本搜索：中位耗时 / P95（ms） | 28.904 / 45.302 | 7.085 / 7.791 |
| 已成功来源重放：写事务数 | 2 | 0 |
| 同一重放：中位耗时 / P95（ms） | 16.629 / 39.668 | 0.525 / 0.662 |
| 16 条消息的完整详情：响应 JSON 字节 | 421,262 | 119,545 |
| 完整详情：中位耗时 / P95（ms） | 9.898 / 10.938 | 7.130 / 13.400 |
| 可选来源摘要详情：响应 JSON 字节 | 未提供 | 43,059 |

完整详情的 P95 在这次小样本中没有改善；摘要模式的收益主要是返回体积，不能据此承诺更低延迟。旧记录没有批量改写，快照体积下降适用于新生成的数据；旧数据仍可使用来源摘要读取。数据库仍需在版本集合中选择当前项，不能将返回行数变少说成所有数据库工作都变成常数。

10 个质量场景中，9 个符合预期：原话、实体别名、带词面交集的改写、显式实体范围、更正后当前内容、历史线索、过去获知视角、无关查询为空，以及原始对话与整理经历混合检索。排名结果、记录数和历史标记前后相同。原始消息、角色和来源 ID 在新增回归中逐项核对；历史版本保留。

已知未解决场景：将“回答请保持简短，先说结论”改写成“答复不要啰嗦”时，没有词面交集，当前无嵌入配置的检索未命中。未加入测试专用同义词。这里的 9/10 是有限场景通过数，不是通用召回率；未覆盖大规模并发、冷缓存、任意自然语言改写或自动项目归属。只读盘点时本机实际数据为 27 个逻辑记忆、53 个版本，最多 3 个版本，因此上述 128 版本场景用于衡量增长后的开销，不代表当前生产规模。

## Agent 对话验收

连接 MCP 后，在独立测试 namespace 中验证以下行为：

1. 输入包含背景、感受和不确定时间的自然语言经历，检查生成的经历是否保留原意。
2. 开启没有前文的新会话，以不同措辞提问，检查能否找到相关经历及原始来源。
3. 让 Agent 归纳认识，检查是否引用经历，并区分用户明确表达与系统推测。
4. 更正原始经历，检查版本是否保留、相关认识是否需要重新审视。
5. 指定过去的 `at`、`known_at`，检查查询和详情读取是否沿用相同时间视角，旧版本命中是否明确标记为历史线索。
6. 在两个 Agent 中使用相同 namespace，检查跨宿主写入与读取。

自动化测试验证结构和调用行为；上述步骤用于评估宿主模型的提取和回忆质量。协议连接成功与模型对话完成应分别确认。

真实时间检查可使用短期规则或计划：设定明确的截止时间，保持服务运行，在截止前后运行 `chronicle state` 和 `chronicle checks` 查看状态。规则应在到期后失效；缺少完成证据的计划应保持结果待确认。

`checks`、`reviews` 的结果为分页对象，读取 `items` 并按 `next_offset` 翻页；不要再按裸列表处理。`reviews --kind understanding` 用于扫描已保存但需要重新核实的认识，此类条目通过 `memory_write` 更新证据和认识。冲突检查处理一次后，仍应能从状态查询看到 conflict，不应无限重复入队。

历史状态 ID 兼容测试仅在随机测试分区构造旧格式节点；真实数据不批量迁移。长中文测试包含 1500 个唯一词；向量测试包含超过初始候选窗口的同一记忆旧版本，使用确定性本地向量。关联查找通过 `EXPLAIN` 检查关系属性索引，不把执行计划当作大数据量延迟测量。

## 桌面端自动采集验收

桌面端自动采集验收应在另一个用户聊天中发送唯一口令，并明确要求助手不调用记忆工具。分别核对 `UserPromptSubmit` / `Stop` 诊断、队列的 `saved` 状态、Neo4j 中同一会话/轮次的用户输入与最终回答，以及 MCP 检索结果。仅有 hook 信任、服务运行或队列接收不能证明已经归档。后台系统会话不应产生用户记忆。

2026-11-12 实机验收：Codex Desktop 会话元数据报告运行时 `0.167.0-alpha.4.1`。新用户聊天仅包含验收输入与“收到”，无工具调用；UserPromptSubmit 和 Stop 均留下队列接收记录，worker 提交后，MCP 能检索同一轮的完整输入与回答。后台非用户会话明确跳过。首次试验中曾只收到 Stop，适配器的当前轮次补齐分支另有回归测试；不能将该分支的单元测试当作所有桌面版本的实际触发证明。

## CI

GitHub Actions 在独立 Neo4j 服务上执行同一套测试和构建。测试凭据仅用于临时服务；真实模型验收需在具备宿主模型凭据的环境单独进行。
